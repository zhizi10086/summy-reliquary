## 0. 阅读说明

### 0.1 三种显示位置（代码里的对应关系）

| 位置 | 观感 | 代码写法 | 说明 |
| --- | --- | --- | --- |
| **聊天框** | 左下角聊天记录，会留痕 | `player.sendSystemMessage(...)` | 重要/长文本（恶魔台词、痛悔短祷、创世纪确认框） |
| **行动栏** | 快捷栏正上方，短暂淡出 | `player.displayClientMessage(..., true)` | 即时反馈（觉醒台词、进度百分比、冷却提示） |
| **物品提示** | 悬停物品时的 tooltip | `appendHoverText(...)` | 风味行 / Shift 功能行 / 门槛行 |

> 注意：`displayClientMessage(component, false)` 才是"发到聊天框"，本模组**没有**用这个重载 —— 所以凡是用 `displayClientMessage` 的都在行动栏。

### 0.2 频率约定

| 标记 | 含义 |
| --- | --- |
| **一次性（终身）** | 落盘在 NBT 里，永久只出现一次（除非 `genesis reset` / 指令重置） |
| **每次条件满足** | 每次触发都会显示（可能有内建冷却或前置判定） |
| **节流 N 秒** | 同一原因在 N 秒内只提示一次（不同原因各自计时） |
| **每 x 秒刷新** | 属于持续进度显示（如蓄力百分比、降临倒计时） |

## 6. 维护提示（新增/修改文本时要知道的事）

1. **只改语言文件**：中英要**同步**加键（`zh_cn.json` + `en_us.json`），代码里不写中文。
2. **多行文本的两种做法**：
   - 需要**逐行延迟**（恶魔台词）→ 用 `DemonDeal` 的行列表 + `DelayedChat`（每行一条消息，间隔可配）；
   - 需要**同一个 tooltip 行内换行** → 用 `\n`（如 `flawless.description.2`）；
   - 长句在 tooltip 里要**自动折行** → 用 `ReliquaryTooltips.wrap(...)`（目前只有痛悔短祷的祷文用）。
3. **颜色不要写进语言文件**，一律在代码里用 `Style.withColor(TextColor.fromRgb(...))` 上色（语言文件里的 `color` 字段只有进度 JSON 用）。
4. **一次性 / 节流的标记**都是玩家 NBT（根标签 `summy_reliquary` 下），例如 `contrition_notified`、`demon_sealed`、`pentagram_message_sent`、`demon_sin_snapshot`（1.6.1 的签约快照）、**`six_drops`（1.6.2 的三类「6」掉落记录，忏悔时也会被清）**；`/summyreliquary genesis reset <玩家>` 会清掉创世纪、痛悔短祷与恶魔交易的一次性标记，**1.6.0 起还会清掉契约（`sacrifice_done` / `pact_signs`）与邪恶度（`evil*` / `hell_locked` / 解锁位图 / 黑心池）并收回契约栏位**，**1.6.1 起一并清掉签约快照，1.6.2 起再清掉 `six_drops`**。
   ⚠️ 1.5.10 起 `demon_sealed` **不再**表示"不能再签"：它只用于①五芒星提示三态 ②抑制自愈补天使；**能不能再签只看"当前是否还持着恶魔标记"**。
5. 恶魔台词的颜色常量在 `DemonDeal.CHAT_RED`（聊天）与 `PentagramItem.TOOLTIP_RED`（提示）；五芒星那句话的呼吸周期在 `PentagramItem.BREATHE_PERIOD_MS`。
   **蓄力反馈已经没有文本**（1.6.3 起）：只有**视野收缩**，比例在 `[demon_deal] charge_fov_scale`（默认 0.20）。
   ⚠️ 1.5.10 曾加的**手持贴图拉伸**（`client/PentagramHandTransform`、X = 1 + 0.30p / Y = 1 + 0.45p）**已在 1.6.2 删除**，1.6.3 也没有恢复。
6. **1.6.3 的 `属性名|数值` 约定**（新增提示行时必须遵守）：
   - 只给**带数值的功能行**用 `|` 拆两段（属性名用派系暗色、数值用派系亮色）；列在 0.3 的派系表里，代码入口是 `ReliquaryTooltips.statLine(...)` / `statComponent(...)`；
   - **叙述句（不含数值的行）不要加 `|`**，它们会按普通灰色显示；
   - 物品名走 `SinTexts.factionName(键, 派系)`；**碎片 / 七罪之源 / 美德**三件已有自定义名字，不要改；
   - 天使 / 恶魔两边**同键同结构**（中英都要有 `|`，否则会退化成整行灰色）。
7. **无敌帧相关的日志不是玩家可见文本**：`[combat] log_iframe_throttle` 只写 `logs/latest.log`（每 5 秒一条，含"尝试 / 落地 / 被挡下 + 来源"），
   用来排查"帧伤"，**不要在语言文件里给它加键**。
6. 所有"数字"都来自配置（`config/summy_reliquary-common.toml`），改配置后提示里的数字会跟着变；不要把这些数字写死在语言文件里（用 `%s` 占位）。
   ⚠️ **1.8.4 口径**：受益方（圣光 / 神圣斗篷 / 圣心 / 炽天使之枪 / 救恩 / 咒印 / 复仇之魂 / 暗仪刺刀）的**联动数值必须用占位符 + 运行时取值**（`Synergies`，或 `VengefulSpirit.effectiveRadius` / `SalvationDomain.radiusFor` / `DemonPact.shatterDamage`）—— 1.8.2 曾把联动值写死在语言文件里，导致**没戴联动件时也显示强化后的数字**，1.8.4 已回退。
   ⚠️ 玄秘魔眼与深渊领主的**亚巴顿专属**描述（「并使目标无法移动」/「满级时目标的抗性提升等级减半」）已拆成独立键 `occult_eye.shift.3.abaddon` / `abyss_lord.shift.4.abaddon`，按 `Synergies.withAbaddon` 条件二选一；**基础键里不要再包含这两句**。同理，契约与深渊领主的联动行只声明「暗仪刺刀已被强化」（献祭匕首 1.8.2 起已改走「献祭」，不再吃遁入暗影的联动）。
7. **口径变更提醒**：① **受伤无敌帧在 1.6.3 已返工** —— 不再是 1.6.2 的自定义节流，而是**沿用原版判定、只改写窗口长度**（字段值 = 有效窗口 + 10；一般 5 tick、帧伤 10 tick），差值结算与 `#bypasses_cooldown` 都交回原版；
② 魂心是**独立池**（`soul_heart_points`，由状态包同步给 HUD），与黑心按"吸收 → 魂心 → 黑心 → 真血"依次结算。
8. **1.6.4：本模组"定值真伤"不允许被加伤改写**（`HolyLightEffect.isExactDamage`）——`revelation_light`（光柱 / 救恩）、
   `godhead_aura`（神性光环）、`sacrifice`（献祭 10000）、`demon_flame`（恶魔之焰 6 点）这四个类型的数值是配置直接给的，
   `SpiritAltarSet.onLivingHurt`（伯列恒之星 +20% / 思想对发光 +10%）会**直接跳过它们**。
   以前是靠启示之光的事件校正顺手盖住，1.6.4 改成伤害标签后必须显式排除，否则光柱会变成 8.4 点/次。圣光（`holy_light`）不在此列。
9. **1.6.4：伤害池与免死/拦截不再读 `LivingDamageEvent` 的金额** —— Kilt 对玩家会发两次该事件、其中一次写回无效，
   所以池子改成 {@code DamagePools} 的"临时并入原版吸收 + 事后拆分"，免死/拦截改成命中前用 {@code DamageEstimate} 估算。
   新增 / 改文案时**不要**再假设"事件金额 = 打到血的那部分"。
10. **1.6.5：池子改成"命中前扣池 + 事后对账"，且完全不再订阅 `LivingDamageEvent`** ——
    原因同上（Kilt 那处 `LivingDamageEvent` 注入在 20.1.20 被直接跳过，日志里能搜到 `exceeds the maximum allowed value: 0`），
    所以任何"依赖该事件"的新文本/新机制都不要再加。
11. **1.6.5：圣心只免疫「恐惧」的减益**（`OccultEye.canFear` 里判断），**不免疫发光、也不免疫注视增伤** ——
    写新文案时别把三件事混成一句（"不敢看你"这类说法会误导）。
12. **1.6.5：注视判定只有一套**（`GazeLook.lookedAt`，思想与玄秘魔眼共用）——距离各自配置、形状都是**单条射线**；
    以后要加"看向就触发"的功能，直接复用这个方法，不要再写第二套。
13. **1.6.7：自定义粒子的 provider 不要走 `RegisterParticleProvidersEvent`** —— Kilt 上那处注入被跳过
    （启动日志 `MinecraftInject ... kilt$postRegisterParticleProviders exceeds the maximum allowed value: 0`），事件不会被 post，
    线上粒子会直接不显示；本模组统一在 `ReliquaryParticles.register()` 里**直接调用 `ParticleEngine#register`**（幂等，Forge 与 Kilt 都成立）。
14. **1.6.7：圣心 / 神性的免疫范围** —— 只免疫「黑暗」与「恐惧」两个减益（新施加的被拦、已有的每秒清），
    **不免疫**注视发光、也不免疫玄秘魔眼的 ×1.3 增伤；写文案时不要把三件事混成一句。
15. **1.6.7：狱火有两个同名但不同的东西** —— `summy-reliquary:hellfire` 既是**伤害类型**（复仇之魂 / 狱火每秒伤害用的法伤口径）
    也是**效果**（深渊领主叠的减益，注册表不同、互不冲突）。深渊领主施加时会排除"定值真伤"与"狱火伤害自身"，改这块逻辑时别把排除项删掉。
16. **1.6.8：致命一击的拦截顺序** —— 神性 → **亚巴顿** → 灵魂免死；亚巴顿"被击杀"与"环境伤害"的分界是
    `source.getEntity() == null`（无攻击者实体 = 环境：虚空 / 挤压 / 窒息 / 仙人掌 / 坠落 / 溺水 / 岩浆……）。
    环境分支**只传送**、保持当前血量、不写冷却、不给无敌与光环；两分支都有各自粒子，但**都没有文本**（冷却中尤其不要加提示）。
17. **1.6.8：范围光环判定的统一口径** —— 复仇之魂 / 救恩 / 神性光环 / 黑心碎裂 / 恶魔光环一律用
    `target.distanceTo(player)`（碰撞箱最近点的 **3D 球形**距离，不是水平圆盘）。新加范围类效果时照抄这套，
    别再写 `sqrt(dx*dx+dz*dz)` 那种圆柱判定；粒子视觉仍按各自美术（如脚底一圈）画。
18. **1.6.9：恶魔线风味行统一上色** —— 恶魔线饰品的 `tagline` 一律走
    `ReliquaryTooltips.demonFlavorLine(tooltip, 键)` / `demonFlavor(键)`（颜色常量 `ReliquaryTooltips.DEMON_FLAVOR_COLOR = 0xC03030`）；

    都**不要**改成这条，加新提示行时按这三类分开挑入口。
19. **1.6.9：成就的"获取类"判据** —— 9 条恶魔线成就里 6 条走 `advancement/ItemObtained#tick` 的**持有物兜底**（每秒扫背包 + Curios），

26. **1.6.10：创世纪是"除成就外全清"** —— 新加/新增状态时记得同步到 `GenesisItem.performReset`（已经清：七罪、天使标记、恶魔线、启示属性、
